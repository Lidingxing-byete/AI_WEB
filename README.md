# 芯诊 AI · 证据驱动的嵌入式 UART 故障诊断工作台

> 全国高校 AI Web 开发挑战赛（B 组）参赛作品。
> 定位：给 STM32F103C8T6 USART 故障排查提供**可追溯、可重复、不硬猜**的 AI 诊断。
> 形态：Web 应用（React + FastAPI），AI 为核，证据纪律贯穿全链路。

## 为什么做这个

嵌入式调试最常见的问题是：**症状一样，原因各异**。"串口不通"可能是时钟没使能、
引脚模式错、波特率对不上、中断没挂 NVIC、printf 没重定向……直接丢给大模型，
它可能自信地给出一个无法验证的结论（幻觉），也可能在材料不足时硬猜。

本项目把"诊断"从"猜"变成"查"：

1. **先查证据，再下结论**：8 个确定性诊断工具解析代码 / 编译日志 / 串口抓帧，
   产出带证据标签的事实，而不是模型拍脑袋。
2. **证据分级，六档标签**：`[实测-硬件] / [实测-仿真] / [静态分析] / [推断] / [假设] / [待验证]`。
   模型输出恒标 `[推断]`，永远无法伪造硬件实测。
3. **材料不足就说不足**：缺代码、缺抓帧时明确列出要补什么，而不是硬给根因。
4. **模型只作解释，来源可切换**：本地 Ollama 小模型 / 云端 DeepSeek 只负责
   "用大白话解释证据 + 补充验证建议"，不参与根因判定；无网 / 无模型时
   自动降级纯规则层，功能不塌。前端一键切换「自动 / 本地 / 云端」。

## 核心能力

| 能力 | 说明 |
|---|---|
| 证据驱动诊断 | 规则层（23 条 UART 结构化规则）+ 8 工具 + BM25 检索自建 40 张知识卡片，端到端留痕 |
| 多步验证工作流 | 候选根因 → 验证步骤 → 用户在真机上回填结果 → 系统据此重排并出报告 |
| 可追溯报告 | 每个结论都挂证据与工具调用记录；重新生成保留历史版本 |
| 模型安全可控 | 三级降级链（云端 DeepSeek→本地 Ollama→规则层）、输出守卫、模型无诊断权 |
| 零部署依赖 | SQLite 单文件 + 本地服务，clone 即跑；密钥零入库（`.env.example`） |

## 架构总览

```
浏览器 (React + TS + Vite + Tailwind + Zustand)
   │  HTTP + SSE（诊断事件实时流）
   ▼
FastAPI (apps/server)
   ├─ 诊断引擎 orchestrator —— 状态机编排 8 个工具，证据链落库
   │    └─ 工具层：T-01 编译日志 / T-02 C 源码 / T-03 UART 配置检查 /
   │              T-04 波特率误差 / T-04r 反推时钟 / T-05 BM25 检索 /
   │              T-06 ISR 体检查 / T-07 串口抓帧解析
   ├─ 语料层：docs/corpus（23 规则 + 40 卡片 + 现象对照表，全部自撰）
   ├─ 模型层：LLM 客户端（urllib 直连 Ollama + DeepSeek，零第三方依赖）+ 输出守卫 + 降级链
   └─ 存储层：SQLite 13 张表（任务 / 证据 / 候选 / 验证 / 报告 / 工具调用留痕…）
```

详细设计见 [`deliverables/技术文档.md`](deliverables/技术文档.md)。

## 快速开始

### 环境要求

- Python 3.11+（开发用 3.13）
- Node.js 18+（开发用 22.x）
- （可选）本地 Ollama `http://127.0.0.1:11434`，已拉取 `qwen2.5-coder:7b`（默认，另有 7b / 3b 备选）
  —— 没有也不影响：自动走纯规则层
- （可选）云端 DeepSeek：在 `apps/server/.env` 填入 `XZ_CLOUD_API_KEY` 即启用
  （默认 `deepseek-chat`，备选 `deepseek-reasoner`）；留空则云端自动跳过，克隆即跑

### 后端

```bash
cd apps/server
python -m venv .venv && .venv/Scripts/activate     # Windows
pip install -r requirements.txt                    # 依赖清单（白名单 3 包：fastapi / uvicorn / pydantic）
python -m uvicorn app.main:app --host 127.0.0.1 --port 8787
# 密钥类配置走环境变量（模板见 .env.example）；留空用内置默认值即可跑。
# 注意：本系统不自动加载 .env 文件——需自定义时以环境变量方式设置，或在 uvicorn 后加 --env-file .env。
```

### 前端

```bash
cd apps/web
npm install
npm run dev          # http://127.0.0.1:5173
```

### 一键回归

```bash
cd apps/server
python run_all_tests.py        # 8 个套件，需后端在跑（评测/冒烟依赖真实服务）
```

## 评测摘要（趋势，非准确率）

固定评测集 **9 用例**（6 正例 + 3 负例），含材料不足、编译错误、超范围三类"坑"。
样本量小，**不足以支撑任何准确率结论**，仅作趋势参考。完整口径见
[`deliverables/测试与评测报告.md`](deliverables/测试与评测报告.md) 与
[`docs/Phase6_评测报告.md`](docs/Phase6_评测报告.md)。

| 维度 | 规则层+工具 | 纯 LLM（qwen2.5:7b，3 次采样） |
|---|---|---|
| 正例 Top-1 命中 | 6/6 | 6/6（打平） |
| 负例误报 | 0 | 1（按实质口径 2） |
| 单次平均耗时 | <10 ms | ~2300 ms |
| 证据可追溯 | 全链可查 | 无 |

> ⚠️ 口径红线：**不得宣称"比大模型更准"**。真实差异是**可追溯、材料不足不硬猜、
> 超范围不套结论、能承载真正的 `[实测-硬件]` 证据**，而非准确率。

## 证据纪律（项目红线）

- 系统内每一条结论都必须带六档证据标签之一；
- **硬件实测只能由用户上板回填产生**，Agent 与模型都无权伪造；
- 模型输出恒标 `[推断]`，经输出守卫校验，失败即降级规则层并留痕；
- 演示数据必须显著标注 `[演示数据，非真实诊断]`。

按范围决策，真实硬件实测**不纳入本期交付**（0/6，如实声明）；T-07 抓帧回填通道与上板方案保留为后续扩展，见
[`docs/Phase5_硬件验证方案与记录模板.md`](docs/Phase5_硬件验证方案与记录模板.md)。

## 合规与版权

- **语料全部自撰**：23 条结构化规则 + 40 张知识卡片 + 现象对照表，
  不使用官方手册原文、不使用他人开源语料（引用开源须声明，本项目零引入）；
- **密钥零入库**：所有密钥走环境变量，提供 `.env.example`，`.env` 已被 `.gitignore` 排除；
- **不执行用户代码**：诊断工具只做静态解析，绝不运行上传的代码；
- 前端零组件库依赖、后端除 FastAPI 白名单外零第三方包（含 LLM 调用均标准库实现）。
