## 三、案例详述

### C1 · USART1 外设时钟未使能

| 项 | 内容 |
|---|---|
| 现象分类 | S1（串口没有输出） |
| 难度 | 入门 |
| 技术依据 | `RM0008` Ch.7 RCC（APB2 外设时钟使能寄存器 `RCC_APB2ENR`）；USART1 挂载于 APB2 总线 |

**故障注入**：在初始化函数中删除（或注释）USART1 的时钟使能调用，其余代码保持不变。

```
// 正确（自撰示例）
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA | RCC_APB2Periph_USART1, ENABLE);

// 注入故障后
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);   // 漏了 USART1
```

**预期现象**（`[待验证]`，Phase 5 实测校准）：
- 串口助手：无任何数据。
- 示波器/万用表：PA9 保持高阻或固定电平，无 UART 波形。
- 程序行为：不崩溃，其余功能（如 LED 闪烁）正常——**这一条是关键判别线索**。

**候选根因（含干扰项）**：

| 候选 | 判定 | 依据 |
|---|---|---|
| ① USART1 时钟未使能 | ✅ **正确根因** | 时钟未开时对外设寄存器的写入不生效，USART 不工作 |
| ② 波特率不匹配 | ❌ 干扰 | 波特率错误通常表现为乱码，而非完全无输出 |
| ③ TX 引脚模式错误 | ❌ 干扰 | 需检查 GPIO_Mode 才能排除 |
| ④ USB-TTL 接线错误 | ❌ 干扰（外部因素） | 需用户确认 TX/RX 交叉与共地 |

**证据检查项**：

| 工具 | 检查内容 | 产出标签 |
|---|---|---|
| `analyze_c_code` | 提取 `RCC_APB2PeriphClockCmd` 的调用参数，比对是否包含 `RCC_APB2Periph_USART1` 与所用端口 | `[静态分析]` |
| `check_uart_config` | 交叉校验「所用 USART 编号 → 所属总线 → 对应时钟使能调用」三者一致性 | `[静态分析]` |
| `search_reference` | 召回「USART1 属 APB2」相关规则卡片 | `[静态分析]` |

**验证步骤**（供用户上板执行）：

| # | 操作 | 测量点 | 预期结果 | 所需工具 |
|---|---|---|---|---|
| V1 | 用 ST-Link 下载基准工程，观察串口助手 | USART1 | 应能收到字符串（确认基准可用） | ST-Link + 串口助手 |
| V2 | 注入故障后重新下载，观察串口助手 | USART1 | 无任何输出 | ST-Link + 串口助手 |
| V3 | 用示波器观察 PA9 电平 | PA9 对 GND | 无起始位下降沿，电平恒定 | 示波器 |
| V4 | 恢复时钟使能后重新下载 | USART1 | 输出恢复 | ST-Link + 串口助手 |

### C2 · 波特率所依据的时钟与实际不符

| 项 | 内容 |
|---|---|
| 现象分类 | S2（串口输出乱码） |
| 难度 | 中级 |
| 技术依据 | `RM0008` Ch.19 USART（波特率发生器，USARTDIV 由 PCLK 分频得出）；USART1 使用 PCLK2 |

**故障注入**：保持代码不变，但**工程实际时钟**与库配置宏所假设的不一致。
典型做法（`[推断]`，具体注入方式在 Phase 2.5 按实际板卡晶振确定）：
- 板载外部晶振为 8 MHz，而 `stm32f10x.h` 中 `HSE_VALUE` 定义为其他值；或
- `SystemInit` 中 PLL 倍频系数与代码注释/文档不符。

这样 `USART_Init` 依据错误的 PCLK2 计算 USARTDIV，实际波特率偏离目标值。

**预期现象**（`[待验证]`）：
- 串口助手：收到乱码（非完全无数据）。
- 示波器：能测到波形，但**单个位宽与目标波特率不符**。
- 判别要点：**降低波特率后可能恢复正常**——低波特率对时钟误差更宽容。

**候选根因（含干扰项）**：

| 候选 | 判定 | 依据 |
|---|---|---|
| ① PCLK2 实际值与配置假设不符，导致波特率偏差超容差 | ✅ **正确根因** | 波特率由 PCLK 分频得到，PCLK 错则波特率错 |
| ② 串口助手波特率设置错误 | ❌ 干扰（外部因素） | 需先核对工具侧设置 |
| ③ USB-TTL 电平不匹配（3.3V/5V） | ❌ 干扰 | 电平问题常表现为乱码或不稳定，需排查 |
| ④ 数据位/校验位配置不一致 | ❌ 干扰 | 需核对 8N1 设置 |

**证据检查项**：

| 工具 | 检查内容 | 产出标签 |
|---|---|---|
| `calc_baud_error` | 依据用户提供的实际时钟树计算实际波特率与误差百分比，与容差阈值比较 | `[静态分析]`（确定性计算） |
| `analyze_c_code` | 提取 `HSE_VALUE` 定义、`SystemInit` PLL 配置、`USART_Init` 波特率参数 | `[静态分析]` |
| `search_reference` | 召回「USART1 用 PCLK2」「波特率容差」规则卡片 | `[静态分析]` |

> **容差阈值说明**：`calc_baud_error` 的容差阈值设为**可配置参数**，初值取工程常用经验值（2%）。
> 该初值**标注 `[待验证]`**，须在 Phase 5 实测中根据实际可通信边界校准，不得在未实测前宣称具体容差数值。

**验证步骤**：

| # | 操作 | 测量点 | 预期结果 | 所需工具 |
|---|---|---|---|---|
| V1 | 核对串口助手波特率与代码设置一致 | 工具侧 | 一致 | 串口助手 |
| V2 | 用示波器测量单个位宽，反算实际波特率 | PA9 | 实测波特率与目标值有偏差 | 示波器 |
| V3 | 将波特率改为 9600 重新下载观察 | USART1 | 若恢复正常，佐证时钟/波特率问题 | ST-Link + 串口助手 |
| V4 | 修正时钟配置宏后按 115200 重测 | USART1 | 输出正常 | ST-Link + 串口助手 |

### C3 · TX 引脚未配置为复用推挽输出

| 项 | 内容 |
|---|---|
| 现象分类 | S3（TX 引脚没有预期波形） |
| 难度 | 入门 |
| 技术依据 | `RM0008` Ch.9 GPIO（端口配置寄存器 CRL/CRH；复用功能输出需配置为复用推挽） |

**故障注入**：

```
// 正确（自撰示例）
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP;      // 复用推挽
GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
GPIO_Init(GPIOA, &GPIO_InitStructure);               // PA9

// 注入故障后
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IN_FLOATING; // 浮空输入
```

**预期现象**（`[待验证]`）：
- 串口助手：无数据。
- 示波器：PA9 无驱动波形（引脚处于输入态，由外部上拉/下拉决定电平）。
- 判别要点：与 C1 现象相似，**必须查代码中的 GPIO_Mode 才能区分**。

**候选根因（含干扰项）**：

| 候选 | 判定 | 依据 |
|---|---|---|
| ① TX 引脚 GPIO_Mode 未设为复用推挽 | ✅ **正确根因** | 复用功能输出需 AF_PP；配成输入则外设无法驱动引脚 |
| ② USART1 时钟未使能 | ❌ 干扰（与 C1 现象重叠） | 需查 RCC 调用排除 |
| ③ 引脚选错（用了非 USART1_TX 的引脚） | ❌ 干扰 | 需核对引脚映射 |
| ④ 硬件虚焊或接线断开 | ❌ 干扰（外部因素） | 需测量通断 |

**证据检查项**：

| 工具 | 检查内容 | 产出标签 |
|---|---|---|
| `analyze_c_code` | 定位 TX 引脚的 `GPIO_Init` 调用，提取 `GPIO_Mode` 实际取值 | `[静态分析]` |
| `check_uart_config` | 校验「TX 引脚 → 应有模式 AF_PP」「RX 引脚 → 输入类模式」一致性 | `[静态分析]` |
| `search_reference` | 召回「USART TX 需 AF_PP」规则卡片 | `[静态分析]` |

**验证步骤**：

| # | 操作 | 测量点 | 预期结果 | 所需工具 |
|---|---|---|---|---|
| V1 | 下载注入故障的工程，观察 PA9 | PA9 对 GND | 无波形 | 示波器 |
| V2 | 将 GPIO_Mode 改回 AF_PP，重新下载 | PA9 | 出现 UART 波形，串口助手收到数据 | 示波器 + 串口助手 |
| V3 | 测量 PA9 空闲电平 | PA9 对 GND | 空闲应为高电平（UART 空闲态） | 万用表/示波器 |

### C4 · USART1 重映射未开启 AFIO 时钟或未调用重映射配置

| 项 | 内容 |
|---|---|
| 现象分类 | S1 / S3（无输出 / TX 无波形） |
| 难度 | 中级 |
| 技术依据 | `RM0008` Ch.9 GPIO（复用重映射与调试 I/O 配置寄存器 `AFIO_MAPR`）；AFIO 时钟位于 APB2 |

**故障注入**：改用 USART1 重映射引脚（PB6/TX、PB7/RX），但漏掉以下之一：
- `RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO, ENABLE);`
- `GPIO_PinRemapConfig(GPIO_Remap_USART1, ENABLE);`

**预期现象**（`[待验证]`）：
- PB6 与 PA9 均无波形；串口助手无数据。
- 判别要点：代码里引脚写的是 PB6，但测量 PB6 无波形。

**候选根因（含干扰项）**：

| 候选 | 判定 | 依据 |
|---|---|---|
| ① AFIO 时钟未开 / 未调用 GPIO_PinRemapConfig | ✅ **正确根因** | 重映射需 AFIO 时钟并使能 MAPR 中对应位 |
| ② 仍按默认引脚 PA9 接线 | ❌ 干扰（外部因素） | 需核对实际接线与代码引脚 |
| ③ USART1 时钟未使能 | ❌ 干扰 | 需查 RCC |
| ④ PB6 被其他外设占用（如 I2C1） | ❌ 干扰 | 需查引脚复用冲突 |

**证据检查项**：

| 工具 | 检查内容 | 产出标签 |
|---|---|---|
| `analyze_c_code` | 检测是否出现 `GPIO_PinRemapConfig` / `GPIO_Remap_USART1`，以及 AFIO 时钟使能 | `[静态分析]` |
| `check_uart_config` | 校验「重映射启用 → AFIO 时钟必须开」「引脚与重映射状态匹配」 | `[静态分析]` |
| `search_reference` | 召回「USART1 重映射引脚与 AFIO 时钟」规则卡片 | `[静态分析]` |

**验证方式标注**：📋 **`[待验证]`** —— 本案例**不做真实硬件实测**（时间预算削减）。
理由：重映射需改接线，与 C1/C3 现象高度重叠，边际信息量低于其他案例。
**文档中必须保留此标注，不得在后续文档中改写为已实测。**

### C5 · 接收中断未挂接 NVIC 或未使能接收中断

| 项 | 内容 |
|---|---|
| 现象分类 | S4（串口接收失败）/ S6（中断或接收处理异常） |
| 难度 | 中级 |
| 技术依据 | `RM0008` Ch.19 USART（中断使能与控制）；`PM0056` / NVIC 相关章节（中断使能寄存器）；USART1 中断号 |

**故障注入**（任选其一，本案例采用"漏 NVIC 配置"）：

```
// 正确（自撰示例）
USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);
NVIC_InitStructure.NVIC_IRQChannel = USART1_IRQn;
NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;
NVIC_Init(&NVIC_InitStructure);

// 注入故障后
USART_ITConfig(USART1, USART_IT_RXNE, ENABLE);
// 漏掉整个 NVIC_Init 配置
```

**预期现象**（`[待验证]`）：
- 发送方向正常（串口助手能收到 MCU 发来的数据）。
- 接收方向无响应：向 MCU 发送数据时，预期的回显/处理不触发。
- 判别要点：**单向正常**是排除波特率与引脚问题的关键线索。

**候选根因（含干扰项）**：

| 候选 | 判定 | 依据 |
|---|---|---|
| ① NVIC 未配置（中断未挂接） | ✅ **正确根因** | 外设中断需经 NVIC 使能才能进入 ISR |
| ② 未调用 USART_ITConfig 使能 RXNE 中断 | ❌ 干扰（本案例的另一半） | 需查 USART_ITConfig |
| ③ 中断服务函数名与启动文件向量表不一致 | ❌ 干扰 | 需核对函数名 |
| ④ 中断标志未清除导致只进一次中断 | ❌ 干扰 | 表现为"只响应一次"而非完全无响应 |

**证据检查项**：

| 工具 | 检查内容 | 产出标签 |
|---|---|---|
| `analyze_c_code` | 提取 `USART_ITConfig`、`NVIC_Init`、`NVIC_IRQChannel`，以及中断服务函数定义 | `[静态分析]` |
| `check_uart_config` | 校验「使能了中断 → 必须有对应 NVIC 配置」「ISR 函数名匹配」 | `[静态分析]` |
| `parse_build_log` | 若 ISR 未定义或重名，检查链接日志是否有相关告警 | `[静态分析]` |

**验证步骤**：

| # | 操作 | 测量点 | 预期结果 | 所需工具 |
|---|---|---|---|---|
| V1 | 下载基准工程，向 MCU 发送字符 | USART1 | 回显正常 | 串口助手 |
| V2 | 注入故障后重下，发送字符 | USART1 | 发送有输出，接收无响应 | 串口助手 |
| V3 | 在 ISR 入口加断点（或翻转一个 LED） | 调试器 | 故障版不进断点 | ST-Link + Keil 调试 |
| V4 | 补上 NVIC 配置后重测 | USART1 | 接收恢复正常 | ST-Link + 串口助手 |

### C6 · printf 未重定向到串口

| 项 | 内容 |
|---|---|
| 现象分类 | S5（初始化看似正常，但程序没有发送数据） |
| 难度 | 入门 |
| 技术依据 | 标准库 `printf` 输出需由用户实现底层字符输出函数并指向 USART；Keil 环境下与 MicroLIB 选项相关 |

**故障注入**：主循环调用 `printf("hello\r\n")`，但：
- 未实现 `fputc`（或 `fputc` 未调用 `USART_SendData`），或
- 未勾选 Keil 工程选项中的 MicroLIB（此情形下可能出现**编译通过但运行异常/无输出**）。

**预期现象**（`[待验证]`）：
- 串口助手无数据；或程序在调用 printf 处异常。
- 判别要点：**直接调用 `USART_SendData` 能发数，但 `printf` 无输出**——这是区分本案例与 C1/C3 的关键。

**候选根因（含干扰项）**：

| 候选 | 判定 | 依据 |
|---|---|---|
| ① printf 未重定向（缺 fputc 实现） | ✅ **正确根因** | printf 本身不知道往哪个外设输出 |
| ② 未勾选 MicroLIB 导致半主机模式相关异常 | ❌ 干扰（环境相关） | 需查编译日志与工程选项 |
| ③ USART 初始化本身有问题 | ❌ 干扰 | 需用 USART_SendData 直发验证 |
| ④ 串口助手未开启显示 | ❌ 干扰（外部因素） | 需核对工具侧 |

**证据检查项**：

| 工具 | 检查内容 | 产出标签 |
|---|---|---|
| `analyze_c_code` | 检测 `printf` 调用；检查是否存在 `fputc` / `USART_SendData` 的组合实现 | `[静态分析]` |
