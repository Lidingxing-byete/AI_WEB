## 一、本次完成了什么

### 1. 报告页 Markdown 可视化（中栏新增「诊断报告」页签）

此前 `/api/tasks/{tid}/report` 端点早已存在（后端生成全文带证据标签的 Markdown），
但前端从未调用——报告只能靠人肉看。本次补齐：

- **`components/markdown.tsx`**：自研轻量 Markdown 渲染器（依赖白名单约束，**不引入任何第三方 Markdown 库**）。
  覆盖报告生成的全部块类型：H1–H4 标题、段落、无序/有序列表（含两级嵌套）、引用块、表格、代码块、
  行内代码、加粗；
- **证据标签识别**：行内代码内容若为 `[实测-硬件]` / `[静态分析]` / `[推断]` 等显示文本，
  或 `STATIC` / `INFER` 等机器短码，渲染为全站一致的 `EvidenceTag` 徽章（按可信度着色），
  而不是普通等宽文本——看报告一眼能认出证据硬度；
- **`components/ReportPanel.tsx`**：拉取 → 渲染 → 「重新生成」（写入新版本，保留历史版本）；
  空态 / 加载态 / 错误态齐全；
- **`api.ts`**：`getReport` 增加 `regenerate` 参数，默认读取**最新已存版本**（不每次点开就生成新版本，
  避免污染 reports 表）；「重新生成」才写新版本；
- **`CenterPanel.tsx`**：中栏顶部加「诊断过程 / 诊断报告」页签切换。

### 2. 任务列表搜索/筛选（左栏）

- 搜索框：按**标题 / 现象描述 / 任务 ID** 子串过滤（不区分大小写）；
- 状态筛选下拉：全部 / 未诊断（created）/ 已诊断·待验证（awaiting_verification）/ 材料不足（insufficient），
  取值与后端一致；
- 每条任务显示状态徽章 + 现象摘要；从"只显示前 8 条"改为**全部**（后端最多返回 50 条）；
- 客户端过滤即可（50 条量级无需后端分页）。

### 3. 验证计划总览（右栏）

- 新增 `VerificationPlanCard`：**跨所有候选根因**汇总验证步骤——
  总步骤数、已完成/待执行、完成度进度条、判定分布（一致/不符/部分/未知）；
- 待办清单逐条列出：步骤文本 + 所属候选 + 状态徽章（待执行 / 已回填+判定）；
- 数据全部来自已落库的 `hypotheses.verifications`（含用户回填的实测结果），前端不做任何推断；
- 回填实测后（在下方案例卡操作）本卡**实时更新**——与"多步诊断/可验证工作流"创新点直接呼应。

### 4. 《项目进度总结_2026-10-25.md》逐项核对（用户指定任务）

> 发现并排掉一个校验脚本自身的坑：报告文件若以 CRLF 落盘，JS 正则 `.*$` 会因行尾 `\r`

> 校验脚本已在读入时剥离 `\r`。渲染器对无 `\r` 的输入是安全的。
