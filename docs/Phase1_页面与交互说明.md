# Phase 1 交付物 ② 页面与交互说明

> 证据标签：本文为 `[推断]`（交互设计推导）。所有界面元素均为设计描述，非已实现的界面。
> 生成时间：2026-10-25。所属阶段：Phase 1。

---

## 一、信息架构（6 个页面）

```
芯诊 AI
├─ P1 任务列表（首页 / Dashboard）
├─ P2 新建任务 + 材料提交（Intake）
├─ P3 诊断工作台 ⭐核心（三栏）
├─ P4 验证执行（Verification）
├─ P5 诊断报告（Report）
└─ P6 知识库浏览（Knowledge）  ← P1 优先级
```

**设计原则**：界面围绕**诊断任务**组织，不以聊天窗口为主体（`PROJECT_PLAN.md` 第六节明确要求）。
对话式输入仅作为「故障现象描述」的一个输入控件存在，不作为主界面形态。

## 二、页面逐一说明

### P1 任务列表

| 区块 | 内容 |
|---|---|
| 顶部 | 系统状态条（模型可用状态、降级提示）、「新建诊断任务」按钮 |
| 主体 | 任务卡片列表：标题、芯片型号、状态徽章、创建时间、候选根因数、最近更新 |
| 空状态 | 「还没有诊断任务」+ 引导建单按钮 + 「查看示例任务」入口（示例显著标注 `[演示数据]`） |
| 异常 | 加载失败 → 错误卡片 + 重试按钮 |

状态徽章配色（状态即信息，不靠颜色单独传达，附文字）：

| 状态 | 文字 | 视觉 |
|---|---|---|
| `draft` | 草稿 | 灰 |
| `analyzing` | 分析中 | 蓝 + 脉冲动画 |
| `awaiting_verification` | 待验证 | 橙 |
| `verifying` | 验证中 | 橙 |
| `resolved` | 已定位 | 绿 |
| `unresolved` | 未定位 | 紫灰（**非红色**，表示"诚实结论"而非错误） |
| `failed` | 失败 | 红 |

---

### P2 新建任务 + 材料提交

**分区表单**（提交前允许部分留空，但需提示「材料越少，证据越弱」）：

| 区块 | 字段 | 校验 |
|---|---|---|
| 基础信息 | 任务标题、芯片型号（默认 STM32F103C8T6）、库类型（标准库 / HAL / 不确定） | 标题必填 |
| 故障现象 | 现象分类下拉（S1–S6）+ 自由描述文本 | 至少填一项 |
| 代码材料 | 文件拖拽上传 / 直接粘贴（**必须填文件路径**，如 `User/usart.c`） | 扩展名白名单；单文件与总量上限 |
| 编译日志 | 粘贴或上传 `.log/.txt` | 非必填，但强烈建议 |
| 串口现象 | 串口助手截图文字 / 实测输出描述 / 波特率与串口工具设置 | 非必填 |

**关键交互**：每次添加材料后右侧实时显示「材料完备度」清单（代码 ✅ / 日志 ⚠️ / 现象描述 ❌），引导用户补全——这是提高诊断质量的关键设计。

---

### P3 诊断工作台 ⭐

**三栏布局**（可折叠）：

```
┌──────────────┬─────────────────────────┬──────────────────┐
│ 左栏          │ 中栏                     │ 右栏              │
│ 任务材料树    │ 诊断时间线（流式）        │ 候选根因面板      │
│              │                          │                  │
│ ├ main.c     │ ▸ 步骤1 解析材料 ✓        │ ① 波特率误差过大 │
│ ├ usart.c    │   └ 工具 parse_build_log │   置信 0.72      │
│ └ build.log  │ ▸ 步骤2 配置检查 ✓        │   ✅支持 x3      │
│              │   └ 工具 check_uart...   │   ❌反对 x1      │
│ [+ 补充材料] │ ▸ 步骤3 知识检索 ⟳        │   [静态分析]     │
│              │ ▸ 步骤4 生成假设 …        │                  │
│              │                          │ ② TX 引脚未复用  │
│              │                          │   置信 0.41      │
└──────────────┴─────────────────────────┴──────────────────┘
```

| 栏位 | 元素 | 交互要点 |
|---|---|---|
| **左栏 材料树** | 已提交材料列表，点击可查看原文（代码高亮） | 分析中允许补充材料 → 触发增量诊断 |
| **中栏 诊断时间线** | 按步骤展开：步骤名、调用的工具、工具输入摘要、工具输出摘要、耗时、状态 | 每个工具调用可展开看完整输入/输出（**可追溯**的关键）；失败步骤显示错误原因，不静默 |
| **右栏 候选根因** | 卡片列表：根因标题、置信度、支持证据数、反对证据数、证据标签、验证步骤入口 | 点击卡片 → 展开证据明细（每条证据含来源、证据标签、原文引用位置） |

**顶部固定**：
- 任务标题与状态徽章
- 模型状态指示（如「云端模型：deepseek-chat / 本地 Ollama 未启用 / 降级模式」）
- 「停止诊断」按钮、`unresolved` 时显示「证据不足，暂不收敛」提示条

**置信度呈现规则**（防止虚假精确）：
- 显示为区间或定性描述（如「较高」「中等」「较低」）+ 数值（保留两位），**不显示为百分比精确到个位**
- 必须同时展示「支持证据」与「反对证据」；若仅有支持证据，标注「未见反对证据（≠ 已排除）」

---

### P4 验证执行

| 区块 | 内容 |
|---|---|
| 验证计划 | 按候选根因分组的验证步骤清单，每条含：操作描述、测量点、预期结果、所需工具（万用表/示波器/串口助手/ST-Link） |
| 结果回填表单 | 每步：实测现象（文本）、是否符合预期（符合 / 不符合 / 不确定）、原始记录（截图上传或文本）、备注 |
| 提交后 | 触发 `record_test_result` → 假设更新 → 返回工作台展示更新后的置信度变化与理由 |
| 安全提示 | 涉及接线/供电的步骤，顶部固定提示「请确认板卡型号、引脚映射与供电条件后再操作」（`PROJECT_PLAN.md` 创新方向 C 要求） |

**关键设计**：**系统不得预填实测结果**。所有实测字段初始为空，Agent 只能给出「预期结果」，不能给出「实测结果」。

---

### P5 诊断报告

结构固定六段：

1. 任务概要（芯片、库、现象、材料清单）
2. 已执行检查（工具调用清单与结论）
3. 候选根因与证据链（含证据标签）
4. 验证过程与实测记录（**用户填写部分显著标注 `[实测-硬件]`，并注明记录人/时间**）
5. 最终结论（已确认 / 未确认 + 理由）
6. 未解决问题与后续建议

操作：导出 Markdown、打印、复制。**导出内容保留全部证据标签**，不得在导出时降级或美化措辞。

### P6 知识库浏览（P1）

| 区块 | 内容 |
|---|---|
| 条目列表 | 自建知识卡片（40 条）：标题、适用芯片、标签、来源引用章节 |
| 详情 | 正文（自撰）、来源引用（如「依据 RM0008 第 19 章 USART」）、适用条件、不适用警告 |
| 检索测试 | 输入查询 → 展示检索命中与排序依据（BM25/规则匹配），供评审核验可追溯性 |

## 三、核心用户操作流程（主流程）

```
P1 列表 → 新建任务
   → P2 填写现象 + 上传 usart.c/main.c + 粘贴编译日志
   → 点击「开始诊断」
   → P3 工作台（流式展示：解析 → 配置检查 → 知识检索 → 假设生成）
   → 用户查看候选根因与证据
   → 进入 P4 验证执行
   → 按步骤上板操作（ST-Link 下载 / 串口助手观察 / 万用表或示波器测量）
   → 回填实测结果
   → 回到 P3 查看更新后的假设（置信度变化 + 理由）
   → 循环 2–3 轮，或标记「已解决」
   → P5 生成诊断报告 → 导出
```

## 四、异常流程清单

| 编号 | 异常 | UI 呈现 | 恢复动作 |
|---|---|---|---|
| E-01 | 上传文件超限 | 内联错误：「文件 3.2MB 超过单文件上限」 | 用户更换/拆分文件 |
| E-02 | 文件类型不在白名单 | 内联错误 + 白名单提示 | 用户转换格式 |
| E-03 | 代码解析失败（非预期语法） | 时间线步骤标记为「解析失败」+ 原因；**不中断整体诊断** | 继续其余检查，报告注明「部分材料未解析」 |
| E-04 | 未检出任何初始化代码 | 提示「未在提交材料中识别到 USART 初始化代码，可能材料不完整」 | 引导补充材料 |
| E-05 | 云端模型超时/报错 | 顶部黄条「模型调用失败，已切换本地模型/规则层」+ 时间线记录失败 | 自动降级，用户可重试 |
| E-06 | 本地模型也不可用 | 顶部黄条「降级模式：仅确定性检查可用，无大模型推理」 | 保留规则层结果，报告注明 |
| E-07 | 模型输出格式非法 | 时间线记录「输出解析失败，已重试 N 次」；重试上限后转降级 | 不把非法输出当结论 |
| E-08 | 工具执行异常 | 时间线步骤显示失败 + 错误摘要；该步骤不产出证据 | 其余步骤继续 |
| E-09 | 证据不足无法收敛 | 右栏显示「证据不足，未给出唯一根因」+ 建议补充的检查项 | 用户补充材料或执行验证 |
| E-10 | 所有候选被证伪 | 提示「全部候选已被实测推翻，建议重新提交材料或扩大范围」→ 进入 `unresolved` | 生成诚实报告 |
| E-11 | 页面断流（SSE 中断） | 显示「连接中断」+ 「重新连接」按钮；已获取内容保留 | 重连续传（基于 trace 增量） |
| E-12 | 存储写入失败 | 全局错误提示 + 任务标记 `failed`，保留现场 | 用户重试或新建任务 |

## 五、证据标签的 UI 呈现规范（差异化核心）

六级标签必须在**每一处结论**旁呈现，不能只在报告里出现一次。

| 标签 | 徽章文字 | 配色 | 出现位置 |
|---|---|---|---|
| `[实测-硬件]` | 硬件实测 | 深绿底白字 | 用户回填的实测结果、被实测确认的结论 |
| `[实测-仿真]` | 仿真实测 | 浅绿 | Keil 仿真结果 |
| `[静态分析]` | 静态分析 | 蓝 | 工具确定性检查结论 |
| `[推断]` | 模型推断 | 橙 | 大模型基于证据的推理 |
| `[假设]` | 假设 | 灰虚线边框 | 尚无证据的猜测 |
| `[待验证]` | 待验证 | 黄 | 计划中未执行的验证 |
| `[演示数据]` | 演示数据 | 紫 | 内置示例任务的全部内容 |

规则：
- 颜色不是唯一区分手段，徽章必须带文字（可访问性）。
- 徽章 hover/点击显示标签定义浮层。
- **任何结论不得无标签**；渲染时若缺少标签，前端显示红色「未标注证据级别」告警（开发期自检）。

## 六、前端工程底线（对应评分项「前端工程质量 10%」）

| 项 | 要求 |
|---|---|
| 最小宽度 | 适配 1280px 及以上（PC 端 Web 为主）；1024px 下降级为双栏 |
| 状态完备 | 每个异步操作都有 loading / success / error / empty 四种状态 |
| 键盘可达 | 主要操作可 Tab 到达，焦点可见 |
| 错误可恢复 | 所有错误提示附带可执行的下一步动作，不只报错误码 |
| 无假加载 | 不使用虚假进度条；真实步骤有真实状态 |
