| 项 | 内容 |
|---|---|
| 目的 | 验证诊断系统能否从「用户材料」走到「候选根因 + 证据 + 验证步骤」，并检验不确定性处理 |

## 二、测试用例通用规格

### 2.1 输入材料规格

| 材料类型 | 必填 | 形式 | 说明 |
|---|---|---|---|
| 代码片段 | ✅ | 文本 + **文件路径** | 至少包含初始化函数与主循环相关片段 |
| 现象描述 | ✅ | 分类（S1–S6）+ 自由文本 | 模拟真实用户的表达，含口语化表述 |
| 编译日志 | 视用例 | 文本 | 部分用例提供，用于测试 `parse_build_log` |
| 串口现象 | 视用例 | 文本 | 串口助手观察到的结果描述 |
| 基础配置 | ✅ | 芯片型号、库类型、波特率 | 表单字段 |

### 2.2 期望输出规格（每个正例）

系统输出必须包含：

| 输出项 | 要求 |
|---|---|
| 候选根因列表 | 至少 2 个（**防止唯一答案式猜测**）；正确根因须在列 |
| 每个根因的证据 | 支持证据 ≥1 条；**显式列出反对证据或声明「未见反对证据」** |
| 证据标签 | 每条证据必须有证据级别标签 |
| 证据可追溯 | 每条证据可点开查看来源（工具调用 ID 或知识卡片 + `source_ref`） |
| 验证步骤 | 针对 Top-1 根因给出 ≥2 条可执行步骤（含操作、测量点、预期结果、所需工具） |
| 置信度 | 带定性描述（较高/中等/较低），并说明置信度依据 |

## 三、正例用例（P-01 ~ P-06）

### P-01 · C1 USART1 时钟未使能

| 项 | 内容 |
|---|---|
| 输入 | `user/usart.c`（含 USART1 与 GPIOA 初始化，但 `RCC_APB2PeriphClockCmd` 参数漏 USART1）、`user/main.c`、现象描述「上电后串口助手完全没反应，LED 正常闪烁」 |
| 编译日志 | 无错误（0 error, 0 warning） |
| 期望 Top-1 | **USART1 外设时钟未使能** |
| 必须出现的证据 | 「`RCC_APB2PeriphClockCmd` 调用参数中未包含 `RCC_APB2Periph_USART1`」`[静态分析]` |
| 必须排除的干扰 | 若将「波特率不匹配」列为 Top-1，判定为**证据误判** |
| 验证步骤要求 | 至少含「用示波器观察 PA9 是否有波形」与「恢复时钟使能后复测」 |
| 陷阱点 | 「LED 正常闪烁」暗示程序在运行，应引导排除"程序没跑"类猜测 |

### P-02 · C2 波特率所依据时钟与实际不符

| 项 | 内容 |
|---|---|
| 输入 | `user/usart.c`（波特率设 115200）、`system_stm32f10x.c`（PLL 配置）、`stm32f10x.h`（`HSE_VALUE` 定义）、现象描述「收到的是乱码，但不是完全没有东西」 |
| 编译日志 | 无错误 |
| 期望 Top-1 | **实际波特率与目标值偏差超出容差** |
| 必须出现的证据 | `calc_baud_error` 给出的**实际波特率数值与误差百分比** `[静态分析]` |
| 必须排除的干扰 | 应先引导「核对串口助手侧波特率设置」再下结论 |
| 验证步骤要求 | 至少含「用示波器测位宽反算实际波特率」 |
| 陷阱点 | 系统**不得**在未获知实际时钟配置时凭空断言误差值；缺信息时应提示补充 |

### P-03 · C3 TX 引脚模式错误

| 项 | 内容 |
|---|---|
| 输入 | `user/usart.c`（PA9 配置为 `GPIO_Mode_IN_FLOATING`）、现象描述「测量 PA9 没有波形」 |
| 编译日志 | 无错误 |
| 期望 Top-1 | **TX 引脚未配置为复用推挽输出（AF_PP）** |
| 必须出现的证据 | 「TX 引脚 GPIO_Mode 实际取值为 `GPIO_Mode_IN_FLOATING`，期望 `GPIO_Mode_AF_PP`」`[静态分析]` |
| 必须排除的干扰 | 与 C1（时钟未使能）现象重叠，须通过 RCC 检查区分 |
| 验证步骤要求 | 至少含「将 GPIO_Mode 改为 AF_PP 后复测 PA9」 |
| 陷阱点 | 若系统只给「时钟未使能」而漏检 GPIO 模式，判定为**检查覆盖不全** |

### P-04 · C4 重映射与 AFIO（静态分析用例）

| 项 | 内容 |
|---|---|
| 输入 | `user/usart.c`（使用 PB6/PB7，调用 `GPIO_PinRemapConfig`，但 RCC 时钟使能中缺 AFIO）、现象描述「换了引脚之后就没输出了」 |
| 编译日志 | 无错误 |
| 期望 Top-1 | **AFIO 时钟未使能（或重映射配置缺失）** |
| 必须出现的证据 | 「检测到 `GPIO_PinRemapConfig(GPIO_Remap_USART1, ...)`，但 `RCC_APB2PeriphClockCmd` 参数未含 `RCC_APB2Periph_AFIO`」`[静态分析]` |
| 验证方式 | 📋 仅静态分析，**本用例不做硬件实测**，结果标注 `[待验证]` |
| 陷阱点 | 若系统建议「检查 PA9 接线」而未识别代码用的是 PB6，判定为**材料读取错误** |

### P-05 · C5 接收中断未挂接 NVIC

| 项 | 内容 |
|---|---|
| 输入 | `user/usart.c`（含 `USART_ITConfig(USART1, USART_IT_RXNE, ENABLE)`，无 NVIC 配置）、`stm32f10x_it.c`（含 `USART1_IRQHandler`）、现象描述「能收到板子发来的数据，但我发给板子它没反应」 |
| 编译日志 | 无错误 |
| 期望 Top-1 | **NVIC 中断未挂接（缺 NVIC_Init 配置）** |
| 必须出现的证据 | 「检测到 `USART_ITConfig` 使能 RXNE，但未找到对应 `NVIC_Init` 配置」`[静态分析]` |
| 必须排除的干扰 | 「单向正常」是排除波特率/引脚问题的关键线索，系统应利用此线索缩小范围 |
| 验证步骤要求 | 至少含「在 ISR 入口设断点或翻转 LED 判断是否进中断」 |
| 陷阱点 | 若系统断言「波特率错误」，判定为**严重误判**（发送正常已排除该可能） |

### P-06 · C6 printf 未重定向（静态分析用例）

| 项 | 内容 |
|---|---|
| 输入 | `user/main.c`（主循环调用 `printf`）、`user/usart.c`（USART 初始化正常，但全工程无 `fputc` 实现）、现象描述「初始化代码看着都对，但就是不发东西」 |
| 编译日志 | 无错误（或含与半主机相关的告警） |
| 期望 Top-1 | **printf 未重定向到串口（缺 fputc 实现）** |
| 必须出现的证据 | 「检测到 `printf` 调用，但未找到 `fputc`/`USART_SendData` 的重定向实现」`[静态分析]` |
| 验证方式 | 📋 仅静态分析，**本用例不做硬件实测**，结果标注 `[待验证]` |
| 陷阱点 | 系统应建议「先用 `USART_SendData` 直发验证硬件链路」——这是区分本案例与硬件故障的关键 |

## 四、负例 / 对抗性用例（N-01 ~ N-03）

> 负例用于检验**不确定性处理**。这类用例的通过标准不是"答对"，而是"**不强行给出唯一根因**"。

### N-01 · 材料严重不足

| 项 | 内容 |
|---|---|
| 输入 | 仅现象描述「串口不通，怎么办」，无任何代码与日志 |
| **期望行为** | 系统**不得**给出唯一根因；应提示「材料不足，无法收敛」并列出需补充的材料清单（代码、编译日志、串口现象） |
| 判定 | 若给出带高置信度的唯一根因 → **不通过**（违反创新方向 A） |
| 对应验收 | 「证据不足时必须显示不确定，不能强行给出唯一根因」 |

### N-02 · 真实问题是编译错误，用户描述为硬件故障

| 项 | 内容 |
|---|---|
| 输入 | 代码看似正常，但编译日志含 `Error: L6218E: Undefined symbol USART_Init` |
| **期望行为** | 系统应**首先**指出链接错误（编译未通过则硬件行为无法讨论），而非直接给硬件类根因 |
| 判定 | 若忽略编译日志直接输出硬件根因 → **不通过** |
| 对应能力 | `parse_build_log` 的触发条件与优先级 |

### N-03 · 材料与首发场景不匹配

| 项 | 内容 |
|---|---|
| 输入 | 提交的是 I2C 初始化代码，现象描述为「I2C 读不到数据」 |
| **期望行为** | 系统应提示「当前仅支持 STM32F103C8T6 的 USART 故障诊断，本次材料超出支持范围」，**不得**硬套 UART 结论 |
| 判定 | 若生成 UART 相关根因 → **不通过**（违反 MVP 范围与防套用要求） |
| 对应能力 | 范围边界提示与 `applicable_chip` 过滤 |

## 五、测试集执行方式

| 项 | 说明 |
|---|---|
| 执行者 | 用户（Phase 6），Agent 记录 |
| 运行次数 | 每个用例至少 **3 次独立运行**（用于观察输出稳定性；样本量小，见局限性） |
| 对照组 | **纯 LLM 基线**：同样材料直接提交给同一云端模型，不带工具与 RAG，比较差异 |
| 记录内容 | 输出快照、工具调用 trace、候选根因与置信度、证据条目、耗时、是否降级 |
| 回归用途 | Phase 6 之后每次重大改动重跑，防止回退 |

## 六、局限性与诚实声明（Phase 6 报告必须包含）

| 局限 | 说明 |
|---|---|
| 样本量小 | 仅 9 个用例（6 正 + 3 负），**不具备统计显著性**，不得据此宣称准确率 |
| 场景单一 | 全部为 STM32F103C8T6 + USART1 + 标准库，不反映其他芯片/外设的表现 |
| 材料由本项目自撰 | 与真实用户工程的复杂度存在差异 |
| 运行次数有限 | 3 次/用例不足以刻画输出波动全貌 |
| 硬件实测仅覆盖 4 例 | C4、C6 仅为静态分析，标注 `[待验证]` |

**硬性要求**：Phase 6 评测报告必须原样包含本节局限性说明，**不得省略或淡化**。
