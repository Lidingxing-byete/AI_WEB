## 三、范围边界

### ✅ 在范围内（要做）

| 维度 | 内容 |
|---|---|
| 目标硬件 | STM32F103C8T6 单芯片 |
| 首发外设 | UART / USART（含 GPIO 配置、时钟、NVIC 关联链路） |
| 首发场景 | UART 无输出、输出乱码、TX 无波形、接收失败、初始化正常但不发送、中断处理异常 |
| 核心能力 | 代码分析、编译日志解析、配置一致性检查、知识检索、证据链呈现、验证步骤生成、实测结果回填 |
| RAG 语料 | **本项目自建**：结构化诊断规则库 + 40 条知识卡片（不使用手册原文、不使用本地知识库原文） |
| 产品形态 | PC 端 Web 应用（诊断工作台，非聊天框） |
| 硬件闭环 | 故障注入 → 诊断 → 上板验证 → 记录 |

### ❌ 不在范围内（明确不做）

| 排除项 | 理由 |
|---|---|
| STM32 其他型号（F0/F4/L0/L4/W1） | 首发只做 F103，扩型号需重新验证资料适用性 |
| GPIO / 定时器 / 中断 / HardFault 等其他外设的完整诊断 | 列入后续扩展，核心闭环未完成前不扩张 |
| 其他编译器（GCC/IAR） | 只支持 Keil MDK |
| 多租户 / 支付 / 权限体系 | 第一版过度设计 |
| 多 Agent 协作 | 同上 |
| 移动端适配 | PC 端优先 |
| 商业化功能 | 非参赛必需 |

## 四、MVP 定义（第一版必须跑通的闭环）

**一个 UART 故障案例，能从输入走到诊断报告。**

```
用户创建诊断任务
  → 上传/粘贴代码片段 + 编译日志 + 故障现象描述
  → 系统提取初始化配置（GPIO/时钟/UART/NVIC）
  → 确定性检查（check_uart_config 交叉核对）
  → RAG 检索参考手册相关章节
  → Agent 生成候选根因（附支持证据/反对证据/置信度）
  → 系统生成验证步骤
  → 用户上板实测并回填结果
  → 系统更新判断
  → 生成诊断报告（区分已确认事实/推断/假设/未验证）
```

**完成判据**（对应 Phase 3 验收）：
- 一个案例能从输入走到诊断报告
- 关键错误有明确反馈
- 能追溯输入、分析过程和证据来源
- 不以演示用硬编码结果冒充真实诊断
