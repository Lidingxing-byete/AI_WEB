## 一、本次完成了什么

### 1. 修掉一个会"抹掉用户实验"的真缺陷（最要紧的一项）

**问题**：`_persist_report` 在每次诊断时执行 `DELETE FROM verifications`，
而用户回填的实测结果存在 `test_results` 表、通过 `verification_id` 外键挂在验证步骤上。
于是——**用户做完实验、回填实测后再补充材料重新诊断，实测记录会全部悬空丢失**，
候选状态也退回 `active`。

这直接违反核心流程第 8 条「用户记录实测结果，Agent 根据结果更新诊断」，
也是创新方向 B（可验证的 Agent 工作流）的关键一环。更糟的是 Phase 5 把
「提交抓帧 → 重新诊断」做成了主路径，等于把这条断线放在了最常用的路上。

**修复**（`app/main.py`）：

| 函数 | 作用 |
|---|---|
| `_snapshot_test_results()` | 重建前按 `(规则号, 步骤序号, 步骤文本)` 快照已回填的实测记录 |
| `_replay_test_results()` | 重建后原样挂回，并重新应用状态（mismatch→refuted / match→confirmed） |
| `_rerank_hypotheses()` | 重排：已确认靠前、已排除沉底，其余按支持度降序 |

匹配键不用自增 id（重跑会变），用语义稳定的三元组，所以候选 id 变了也能挂回原处。

**顺带修的第二个 bug**：`_rerank_hypotheses` 里把 `(tid)` 写成了参数——
Python 中这不是元组，sqlite3 会按字符序列绑定导致异常。
这个错误还造成了一次**假通过**：重诊断实际已 500，但界面看起来"回填还在"
（因为旧的 verification 根本没被重建）。已补上状态码断言，杜绝这类假阳性。

### 2. 前端：工具面板（可解释性 / 工具集成评分项）

新增 `components/ToolPanel.tsx`：把 8 个诊断工具全部摊开，逐个显示
中文职责、工具名、默认证据等级、**本轮是否执行/跳过/失败**、失败原因。
数据来自 `/api/tools` + 本轮 `/tool-runs` 留痕，前端不做任何推断。

答辩价值：「你的 Agent 到底做了什么」不用靠嘴说，直接看这一栏。

### 3. 前端：样例库分组 + 一键演示

- 12 个样例按 **C1–C6 分组**，每组「故障版 / 对照版」成对，颜色区分；
- 每组标题直接显示**预期命中的规则号**（后端 `expect_rules` 给出，前端不硬编码）；
- 点一下 = 建任务 + 提交源码 + 跑完诊断，全程自动（此前需要点三次）；
- 底部固定提示：示例是人为注入的自撰故障，标 `[演示数据]`，不是真实板卡现象。

### 4. 前端：预期命中 vs 实际命中

右栏新增对照卡：列出预期规则、实际命中、**漏检**、**多报**，给出「与设计一致 / 存在偏差」。
把演示从"看起来对"变成"可核对"。

严谨性：卡片上明确写「预期规则是样例设计声明 `[待验证]`，未经硬件实测；
此处只核对静态检查是否符合设计，不代表板卡真实现象」——防止被误读成实测证据。

### 5. 前端：状态与恢复

- 顶部新增**后端连通状态灯**；后端不可达时显示红色横幅 + 启动命令 + 「重试」按钮，
  而不是让界面停在"看起来正常"；
- 已诊断但零候选时，顶部提示区分「材料不足」与「确实没问题」；
- 验证步骤显示「已回填」标记与实测原文，可「重新回填」覆盖；
- 工具名中文映射抽到 `ToolPanel.tsx` 单点维护，消除中栏与面板的重复。

### 6. 一键回归入口 `run_all_tests.py`

聚合 6 个测试套件。设计上刻意做了两件事：

- 子脚本退出码非 0 即判失败，不做"差不多"容错；
- 依赖后端而后端没起时判 **SKIP，绝不计入通过**（跑不了就是没验证）。

本机首次运行正好演示了这个行为：后端被回收 → e2e 显示「未验证（不计入通过）」。

### 7. 交付物 `deliverables/运行说明.md`

安装、运行、踩坑记录、一键自检、**5 步演示脚本**（每步都有预期结果，可核对）、
硬件通道说明、目录速查。评审 clone 后按此文档可跑通。
