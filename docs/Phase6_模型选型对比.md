- **目的**：judge 口径与 `service.baseline()` 允许的哨兵值一致，正确拒绝不算硬给根因；
- **影响**：仅 `eval/llm_baseline.py` 的统计判定，不影响引擎 / API / 报告 / 其它套件；
- **回滚**：还原该分支条件即可；
- **复现**：三个模型均用修正后代码重新跑，本文件全部数字出自同一代码同一口径。

## 4. 定性解读（仅趋势，不构成统计结论）

- **正例上三者与规则层打平**（除 3b 丢 P-05），说明"给足材料时本地模型能定位常见 UART 故障"；
- **负例（防坑）是最大分水岭**：coder:7b 三个坑全避开，7b 本批踩 2 个，3b 踩 1 个硬猜 + 1 个硬套；
- **N-02 编译错误用例**只有 coder:7b 答对——与它接受过代码训练的背景一致，是选型加分项；
- **3b 优势仅速度**（约 0.9s），代价是正例丢 1、负例不稳；
- **稳定性**：coder:7b 9/9 三次一致；7b 7/9（N-01/N-03 抖动）；3b 8/9。
- ⚠️ 单模型单日各一次采样；本地小模型存在抖动，以上**不可外推为准确率**。

## 5. 选型结论与建议

1. **默认模型 → `qwen2.5-coder:7b`**：趋势上正例不输 7b、负例防坑更好、输出最稳、还答对了编译错误用例；速度与 7b 相当（同为 7B 级）。**该切换是配置级变更（`XZ_LLM_MODEL` 默认值），已列入待决策项，未擅自修改**。
2. **3b 保留为"无 GPU / 弱机"选项**：速度最快，可作演示降级备选；不推荐默认（正例丢分）。
3. **口径红线不变**：不得宣称"比大模型更准"；9 用例只作趋势；模型在系统中恒 `[推断]`、无诊断权——选型只影响"解释质量/防坑倾向"，不影响结论的可信度分层。
