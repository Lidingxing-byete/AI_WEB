## 一、环境要求（已在本机实测确认）

| 项 | 要求 | 说明 |
|---|---|---|
| Python | 3.10+（本项目用 3.13.14 实测） | 需可用 `python` 命令 |
| Node | 18+ / 22.x（本项目用 22.22.2 实测） | 需可用 `npm` 命令 |
| 操作系统 | Windows / macOS / Linux 均可 | 本机为 Windows 10 实测 |
| 浏览器 | Chrome / Edge（WebSocket/SSE 与 Web Serial 需要） | 已装 |
| 数据库 | 无需安装，SQLite 文件随仓库生成 | — |
| 网络 | **不联网也能跑**：无云端模型依赖 | — |

依赖极简，后端只三个包：`fastapi`、`uvicorn`、`pydantic`。
前端：`react`、`react-dom`、`typescript`、`vite`、`@vitejs/plugin-react`、`tailwindcss`、`zustand`。

---

## 二、安装

```bash
# 后端（Python 3.10+，建议建独立 venv）
cd apps/server
python -m pip install fastapi "uvicorn[standard]" pydantic

# 前端
cd apps/web
npm install
```

> 本机 pip/npm 依赖**已装好**，`node_modules` 不入库，换机才需要重装。

## 三、运行

**必须先启动后端，再启动前端。** 两个都用后台方式常驻，不要直接关终端。

```bash
# 1) 后端（127.0.0.1:8787）
cd apps/server
PYTHONIOENCODING=utf-8 python -m uvicorn app.main:app --host 127.0.0.1 --port 8787

# 1.5) 本地模型（可选，127.0.0.1:11434）
#     不启动也能用：系统会自动降级为纯规则层，诊断照常完成
ollama serve

# 2) 前端（127.0.0.1:5173），vite 已配 /api 代理到 8787
cd apps/web
npm run dev
```

打开 <http://127.0.0.1:5173>。

**模型相关**（本地 Ollama + 云端 DeepSeek，零新增依赖）：

- 默认模型 `qwen2.5-coder:7b`（本机已拉取；2026-10-25 三模型基线对比选定，
  备选 `qwen2.5:7b` / `qwen2.5:3b`）。**演示前建议先预热一次**——
  首次调用要把 4.4GB 权重载入显存，可达数十秒，之后单次约 2–3 秒。
- 界面中栏「模型解读」卡可开关。关闭即纯规则层，**结论不受影响**。
- 卡内可切换模型来源：**自动（云端优先）/ 本地 Ollama / 云端 DeepSeek**。
  云端未配置密钥时自动跳过（状态区如实显示「未配置」，不会假装已接入）。
- 模型只解释已查出的结论、补充验证建议，**不参与根因判定**；
  输出恒标 `[推断]`，且必须先过证据纪律守卫。

**坑位记录**（本机实测踩过）：

- 后端**不要用 `--reload`**，本机环境下改动不生效，改完代码请手动重启进程。
- 若本机配置了 HTTP 代理：本地 Ollama 已用 `ProxyHandler({})` 绕过（直连 127.0.0.1）；
  云端 DeepSeek 则**走系统代理**出公网（勿配 `_NO_PROXY` 到云端）。
- 后端未启动时，前端顶部会显示红色「后端未响应 + 重试」横幅，不会假装正常。

## 五、演示脚本（3 分钟，全程可重复）

演示路径**不依赖任何临时人工修改**，点一下即可跑完。

### 第 1 步：故障命中（C1 串口无输出）

左栏「内置示例」→ **C1 故障版**。系统自动建任务、提交源码、跑完诊断。

预期看到（`[静态分析]`）：

- 中栏时间线：8 个工具逐步执行，实时 SSE 推送，含耗时与跳过原因；
- 中栏「诊断工具」：8 个工具全摊开，标明本轮哪些执行 / 跳过 / 失败；
- 右栏 1 条候选根因「USART1 外设时钟未使能」（规则 `R-S1-01`）；
- 右栏「预期命中 vs 实际命中」：显示与设计一致；
- 中栏「无法判定的项」：列出查了但判不了的内容（**不包装成结论**）。

### 第 2 步：对照不误报

左栏 → **C1 对照版**。

预期：候选根因为 **0 条**，页面顶部提示「未检出配置违规」。
这一步专门证明系统不是"遇事就报时钟问题"。

### 第 3 步：多步诊断 + 实测回填（C5）

左栏 → **C5 故障版**（双重故障：缺 NVIC + ISR 未读 DR）。

1. 右栏出现 2 条候选，验证步骤可展开；
2. 点任一步「回填实测」，填写观测值与判定（如 `与预期不符`），提交；
3. 该候选**状态变「已排除」并沉到最后一位**——证明系统听见了用户反馈；
4. 再点「重新诊断」，实测回填**仍然在**（这是 Phase 7 修掉的一个真缺陷：原先重诊断会把它清空）。

### 第 4 步：证据边界（负例，可选）

新建任务，只填「串口不通，怎么办」就诊断。

预期：**不给根因**，返回「材料不足」并列出需要补充什么。
再提交一段 I2C 代码：预期**不套用 UART 结论**，提示可能超出支持范围。

### 第 5 步：报告导出

`GET /api/tasks/{id}/report?regenerate=true`，或在界面取报告。
报告含六章：候选根因与证据、无法判定项、参考卡片、诊断过程、待补充信息、硬件实测记录。
**每条结论都带证据等级标签。**

## 六、硬件实测通道（后续扩展，当前 0 条）

按用户 2026-10-25 决策，硬件实测**不纳入本期交付**；通道与上板方案保留，供后续扩展随时回填：

- 左栏「硬件实测记录」粘贴串口抓帧 → 后端 `parse_serial_capture` 做确定性判读
  （EMPTY / GARBLED / NORMAL；样本过短判 UNKNOWN，**不硬判**）；

## 七、环境变量

**不依赖任何环境变量**（密钥留空即克隆即跑）。以下均为可选覆盖：

| 变量 | 默认 | 说明 |
|---|---|---|
| `XZ_LLM_ENABLED` | `1` | 设为 `0` 关闭模型层，系统退回纯规则层 |
| `XZ_LLM_MODEL` | `qwen2.5-coder:7b` | 本机已拉取的模型，切换不会下载新模型 |
| `XZ_OLLAMA_HOST` | `http://127.0.0.1:11434` | 仅本机 |
| `XZ_LLM_TIMEOUT_S` | `120` | 需覆盖冷启动（权重载入显存） |
| `XZ_LLM_BASELINE_REPEAT` | `3` | 基线对比的采样次数 |
| `XZ_LLM_PREFERRED` | `auto` | 模型来源偏好：`auto`=云端就绪优先否则本地；`local`=固定本地；`cloud`=固定云端（失败自动降级本地）。前端切换控件写入同值 |
| `XZ_CLOUD_PROVIDER` | `deepseek` | 云端 provider 标识 |
| `XZ_CLOUD_MODEL` | `deepseek-chat` | 云端模型（备选 `deepseek-reasoner`） |
| `XZ_CLOUD_BASE_URL` | `https://api.deepseek.com` | OpenAI 兼容端点 |
| `XZ_CLOUD_API_KEY` | （空） | **填入即启用云端**；留空即不启用，不会"半配置"运行。密钥只走环境变量，绝不入库 |
| `XZ_CLOUD_TIMEOUT_S` | `60` | 云端请求超时（云端无冷启动） |

云端启用方法：复制 `apps/server/.env.example` 为 `.env`，填 `XZ_CLOUD_API_KEY` 后重启后端。
生效验证：打开页面，「模型解读」卡状态区显示「云端在线」；未填密钥时显示「云端未配置」。
